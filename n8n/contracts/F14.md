# Contrato F14 - Cierre contable mensual

Flujo n8n: `vKH6kUKzwUPrqVNC` (inactivo). Dia 1 de cada mes, 6:00 America/Bogota. Endpoints **no existen aun**.

Reglas comunes de `/api/internal/*`: ver `F01.md`. Lista de tenants: `GET /api/internal/notification-targets?flow=F14` (definido en `F09.md`, seccion 0; incluye `accountant.configured` y `accountant.opt_in`).

El **contador es un tercero**: el flujo solo le entrega datos si el dueno tiene opt-in Y dio consentimiento explicito para enviarle el export (`accountant.opt_in`). Al dueno se le avisa por I02; el envio al contador es un nodo de correo que se conecta manana (hoy es un marcador `PENDIENTE DE CONECTAR`).

## 1. GET /api/internal/tenants/{tenant_id}/accountant-contact

```json
{ "tenant_id": "t-demo-1", "accountant_email": "<correo registrado>", "accountant_opt_in": true }
```

- Solo se devuelve si `accountant_opt_in = true`; si no, 404/403. El correo se usa unicamente en el nodo de correo; **no se escribe** en repo, tablas n8n ni mensajes. Recomendado: guardar solo la ejecucion de error en n8n (sin datos de exito).

## 2. GET /api/internal/tenants/{tenant_id}/accounting-export?period=YYYY-MM&format=csv

Mismo contenido que `GET /api/reports/accounting-export` para el mes `period` (el flujo pide el mes anterior en America/Bogota). Respuesta: archivo (`text/csv`, `Content-Disposition` con nombre). Contexto `app.current_tenant_id = {tenant_id}`; nunca filas de otro tenant. `period` invalido o futuro -> 400.

## Logica en n8n

- Una vez por periodo: clave `F14:{tenant}:{YYYY-MM}` (I02 deduplica el aviso). Reejecutar el flujo el mismo mes no duplica el aviso; el reenvio del correo al contador debe protegerse igual al conectar el nodo (comprobar la bitacora antes de enviar).
- Aviso al dueno: "Cierre contable {periodo}: el archivo quedo preparado / se envio a tu contador". Severidad `info`.

## Cambios de backend / BD requeridos

1. Endpoints 1 y 2, `notification-targets` y router `/api/internal`.
2. **Email del contador por tenant** y **consentimiento** (`notification_prefs.accountant_email`, `accountant_opt_in` con fecha) editable por el dueno en la app.
3. `accounting-export` con parametro de periodo mensual y formato CSV si hoy solo acepta rangos de fechas.
4. Credencial de correo (SMTP) en n8n al conectar el envio; no se versiona.
