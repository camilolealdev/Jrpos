## 1. GET /api/internal/tenants/{tenant_id}/cash-sessions/{session_id}/closing-summary

Resumen del cierre de una sesion de caja ya cerrada. Se ejecuta con `app.current_tenant_id = {tenant_id}`: si la sesion no pertenece a ese tenant responde 404 (nunca datos de otro tenant).

Respuesta 200:

```json
{
  "tenant_id": "t-demo-1",
  "session_id": "ses-100",
  "register_name": "Caja 1",
  "closed_at_local": "2026-10-13 21:05",
  "expected_amount": 850000,
  "counted_amount": 805000,
  "difference": -45000,
  "threshold": 20000,
  "currency": "COP",
  "notify": { "opt_in": true, "channel": "whatsapp" }
}
```

- `difference` = contado - esperado (negativo = faltante, positivo = sobrante). Numerico, en la moneda del tenant.
- `threshold`: umbral propio del tenant (valor absoluto); `null` si no tiene. n8n usa entonces `cash_diff_threshold_default` de `jrpos_config` (hoy 20000).
- `notify.opt_in`: solo true con opt-in vigente en `notification_prefs`. Sin opt-in n8n no envia.
- No devolver nombre del cajero ni telefonos. `register_name` es el nombre de la caja, no de una persona.
- n8n descarta la respuesta si `tenant_id` no coincide con el pedido.

## Eventos y n8n
