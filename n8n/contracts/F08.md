# Contrato F08 - Renovacion y reactivacion

Flujo n8n: `ti75RBmWMpzzIs8o` (inactivo). Reglas comunes de auth, multi-tenant y datos personales: ver `F01.md`. Los dos endpoints **no existen aun**. Ambos corren con contexto de superadmin solo para listar y devuelven un registro minimo por tenant.

## 1. GET /api/internal/tenants/renewals?days_ahead=5

Tenants con suscripcion `active` cuyo `TenantSubscription.current_period_end` cae entre hoy y `days_ahead` dias (fecha en America/Bogota).

Respuesta 200:

```json
{
  "tenants": [
    {
      "tenant_id": "t-demo-1",
      "status": "active",
      "plan": "pro",
      "current_period_end": "2026-10-18",
      "days_left": 5,
      "opt_in": true,
      "channel": "whatsapp",
      "payment_url": "https://app.example/pagar?t=<token-corto-de-un-solo-tenant>"
    }
  ]
}
```

- `current_period_end`: fecha `YYYY-MM-DD`. El flujo avisa cuando `days_left` esta entre 3 y 5 (ventana de reintento si un dia falla) y usa la clave `F08:renovacion:<tenant_id>:<current_period_end>` (un aviso por periodo).
- `status`: el flujo solo envia a `active`; suspendidos o cancelados no deben aparecer.
- `payment_url`: enlace de pago/renovacion del tenant (hoy el cobro es manual por Nequi/QR; puede ser la pagina de planes). Sin datos personales.
- `opt_in` / `channel` provienen de `notification_prefs`.

## 2. GET /api/internal/tenants/inactive?days=7

Tenants `active` (suscripcion o trial vigente) sin ventas completadas en los ultimos `days` dias.

Respuesta 200:

```json
{
  "tenants": [
    {
      "tenant_id": "t-demo-2",
      "status": "active",
      "days_without_sales": 9,
      "opt_in": true,
      "channel": "whatsapp"
    }
  ]
}
```

- `days_without_sales`: dias enteros desde la ultima venta (o desde el registro si nunca vendio). Debe ser >= `days`.
- Excluir suspendidos y tenants con onboarding en curso (F07) si se quiere evitar doble mensaje; F08 no lo comprueba.
- El flujo limita el empuje a uno por semana ISO y tenant: clave `F08:inactividad:<tenant_id>:<anio-semana>`.

## Reglas

- Solo identificadores, contadores y enlaces; nada de nombres, telefonos ni correos.
- Un tenant nunca aparece con datos de otro tenant; el telefono/correo lo resuelve el canal de I02.
- Timeout de n8n: 15 s; si falla el endpoint, ese dia no se avisa (el siguiente sondeo diario lo recupera mientras `days_left` siga entre 3 y 5; la ventana de 3 a 5 dias permite recuperar hasta 2 dias perdidos sin duplicar, porque la clave es por periodo).
