# Contrato F01 - Ciclo de vida del trial

Flujo n8n: `LUWm0nYxw2ozLDJV` (inactivo). Consume dos endpoints internos que **no existen aun**.

## Reglas comunes (aplican a todos los endpoints `/api/internal/*`)

- Auth: `Authorization: Bearer <INTERNAL_API_TOKEN>` (credencial n8n Header Auth `JRPOS Internal Token`). Comparacion en tiempo constante. Si `INTERNAL_API_TOKEN` no esta definido, el router responde 404.
- Multi-tenant: un endpoint que lista entre tenants corre con contexto de superadmin y devuelve solo campos de negocio minimos por tenant; cualquier dato de un tenant concreto se obtiene con `app.current_tenant_id` fijado a ese tenant. Nunca mezclar datos de dos tenants en una misma respuesta de negocio.
- Sin datos personales innecesarios: no devolver telefono, correo ni nombre de personas. El telefono/correo de entrega lo resuelve el canal de I02 a partir de `tenant_id` y `notification_prefs`.
- Tiempos limite: n8n espera 15 s. Errores 5xx no deben tener efecto parcial.

## 1. GET /api/internal/tenants/expiring

Lista tenants cuyo trial vence en la ventana indicada. `days_left` se calcula en America/Bogota (fecha de `trial_ends_at` menos fecha de hoy).

Query:

| Param | Tipo | Defecto | Descripcion |
|---|---|---|---|
| `days_ahead` | int | 5 | Incluye tenants con `days_left` entre 0 y `days_ahead` |
| `days_back` | int | 1 | Incluye tenants vencidos hace hasta `days_back` dias (`days_left` negativo) |

Respuesta 200:

```json
{
  "generated_at": "2026-10-13T14:07:00Z",
  "tenants": [
    {
      "tenant_id": "t-demo-1",
      "status": "trial",
      "trial_ends_at": "2026-10-18",
      "days_left": 5,
      "opt_in": true,
      "channel": "whatsapp",
      "paywall_url": "https://app.example/paywall?t=<token-corto-de-un-solo-tenant>"
    }
  ]
}
```

- `status`: `trial` | `expired` | `suspended`. Solo se devuelven tenants con `trial_ends_at` en la ventana y que nunca hayan tenido suscripcion activa.
- `opt_in`: true solo si `notification_prefs` tiene opt-in vigente para ese canal. Sin opt-in n8n no envia.
- `channel`: canal preferido del dueno (`whatsapp` | `email`).
- `paywall_url`: enlace al paywall de ese tenant; no debe contener datos personales.
- Vacio: `{"tenants": []}`.

## 2. POST /api/internal/tenants/{tenant_id}/mark-expired

Marca `Tenant.status = 'expired'` de forma proactiva. Idempotente.

Body:

```json
{ "reason": "trial_ended", "idempotency_key": "F01-expire:t-demo-1:2026-10-13" }
```

Reglas: solo transiciona `trial -> expired` si `trial_ends_at` ya paso; si ya esta `expired` o `active`, no cambia nada. Respuesta 200:

```json
{ "tenant_id": "t-demo-1", "status": "expired", "changed": true }
```

Debe dejar rastro en `tenant_audit_logs`. 404 si el tenant no existe; nunca revela existencia de otros tenants.
