# Contrato F02 - Reporte diario del dueno

Flujo n8n: `TipgBLFStSx9c5l2` (inactivo). Reglas comunes de auth, multi-tenant y datos personales: ver `F01.md` (seccion "Reglas comunes"). Endpoints **no existentes aun**.

## 1. GET /api/internal/tenants/digest-recipients

Lista los tenants que deben recibir el reporte hoy: `status = active` (o `trial` vigente), con `notification_prefs` con opt-in al reporte diario. Solo identificadores y preferencias; nada de cifras ni contactos.

Respuesta 200:

```json
{
  "tenants": [
    { "tenant_id": "t-demo-1", "opt_in": true, "channel": "whatsapp" }
  ]
}
```

- `channel`: `whatsapp` | `email`. El telefono/correo no se devuelve: lo resuelve el canal de I02 a partir de `tenant_id`.
- Tenants suspendidos, expirados o sin opt-in no aparecen (n8n igualmente filtra `opt_in`).

## 2. GET /api/internal/tenants/{tenant_id}/daily-digest?date=YYYY-MM-DD

Resumen agregado del dia (zona America/Bogota) de **un solo tenant**. Corre con `app.current_tenant_id = tenant_id`. Las cifras deben coincidir con `GET /api/reports/summary` del mismo dia.

Respuesta 200:

```json
{
  "tenant_id": "t-demo-1",
  "date": "2026-10-13",
  "currency": "COP",
  "sales_total": 1250000,
  "sales_count": 42,
  "margin_pct": 31.5,
  "cash": { "expected": 980000, "counted": 975000, "difference": -5000 },
  "credits_pending_total": 340000,
  "low_stock_count": 3
}
```

Reglas:

- Solo agregados. Sin nombres de clientes, deudores, empleados ni telefonos (el texto va a un modelo de IA y a un canal externo).
- `cash` puede ser `null` si no hubo arqueo ese dia.
- `low_stock_count`: criterio de "stock bajo" pendiente de definir (ver F09 / `min_stock`); hasta entonces puede devolver 0.
- 404 si el tenant no existe o no esta habilitado; nunca devolver datos de otro tenant.
- n8n usa timeout de 20 s; si falla, se omite ese tenant ese dia (no se reintenta con datos parciales).
