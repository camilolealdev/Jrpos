## 1. GET /api/internal/tenants/{tenant_id}/credits/top-debtors?limit=N

Mayores deudores del tenant (fiado). Reutiliza la logica de `GET /api/credits/summary` y `/credits/customer/{id}`. Contexto `app.current_tenant_id = {tenant_id}`. `limit` 1-20 (n8n manda `cartera_top_n`, hoy 5).

```json
{
  "tenant_id": "t-demo-1",
  "total_outstanding": 2350000,
  "debtors_count": 12,
  "overdue_total": 900000,
  "debtors": [
    { "customer_id": "c-12", "display_name": "Maria P.", "balance": 400000, "days_overdue": 35, "wa_me_link": null }
  ]
}
```

- Ordenado por `balance` descendente. `display_name` = nombre de pila + inicial del apellido (minimo necesario para que el dueno lo reconozca).
- `wa_me_link`: **opcional**. Solo se incluye si el tenant lo activa; contiene el telefono del deudor, asi que por defecto es `null` y el mensaje usa el enlace de la app (`{app_base_url}/credits/customer/{customer_id}`). n8n solo lo usa si `jrpos_config.cartera_include_wa_links = true`.
- `days_overdue`: 0 si no esta vencido. Sin cedula, direccion ni telefono.
- Sin deudores: `total_outstanding: 0`, `debtors: []` (n8n no envia nada).
