## 1. GET /api/internal/tenants/{tenant_id}/inventory/rotation-merma?no_sales_days=90&merma_days=30

Contexto `app.current_tenant_id = {tenant_id}`.

```json
{
  "tenant_id": "t-demo-1",
  "no_sales": {
    "days": 90,
    "count": 14,
    "stock_value": 1200000,
    "top": [ { "name": "Producto X", "stock_value": 300000 } ]
  },
  "merma": {
    "window_days": 30,
    "total_value": 180000,
    "products": [ { "name": "Leche", "window_value": 90000, "avg_window_value": 30000 } ]
  }
}
```

- `no_sales`: productos activos con stock > 0 y **sin ventas** en `no_sales_days`. `count` y `stock_value` (stock x costo) son del total; `top` = hasta 3-5 por valor. Consulta NUEVA (ultima venta por producto).
- `merma.window_value`: valor de merma del producto en los ultimos `merma_days`; `avg_window_value`: promedio historico por ventana equivalente (p. ej. ultimos 90 dias / 3). Debe cuadrar con `GET /api/reports/merma` para el mismo periodo.
- n8n marca anomalia si `window_value > 0` y (`avg_window_value == 0` o `window_value / avg_window_value >= merma_anomaly_ratio`, hoy 2).
- Sin datos personales.

## Logica en n8n

- Si no hay productos sin rotacion ni anomalias, **no se envia nada**. En otro caso UN resumen por tienda y semana (clave `F13:{tenant}:{semana ISO}`).
- Severidad `info`; solo dueno con opt-in. Tope 1400 caracteres.
