# Contrato F03 - Soporte

Flujo n8n: `UWsVfxqJ90BpS5Yu` (inactivo). Reglas comunes de auth, multi-tenant y datos personales: ver `F01.md`. Los endpoints y el evento **no existen aun**.

## Entrada: evento `ticket.created` (backend -> I05 -> F03)

I05 valida token, ventana de 300 s y duplicados, y reenvia por Execute Workflow a F03 con `event_id`, `type`, `tenant_id`, `data`.

```json
{
  "event_id": "evt-0002-ejemplo",
  "type": "ticket.created",
  "tenant_id": "t-demo-1",
  "timestamp": 1791867000,
  "data": {
    "ticket_id": "tk-101",
    "subject": "No puedo cerrar la caja",
    "message": "Texto del ticket, maximo 600 caracteres",
    "priority": "alta",
    "created_at": "2026-10-13T14:00:00Z"
  }
}
```

- `priority` es la del usuario (`baja|media|alta|urgente`). El flujo la usa como minimo y la IA solo puede subirla.
- `subject` y `message` salen hacia un modelo de IA externo: el backend debe truncarlos y no incluir datos personales evidentes del solicitante (sin telefono, correo ni nombre).
- El aviso al superadmin lleva solo `ticket_id`, `tenant_id`, urgencia y asunto.

## 1. PUT /api/internal/tickets/{ticket_id}/triage

Guarda la clasificacion y una nota sugerida en el ticket (reemplaza el uso de `PUT /api/superadmin/tickets/{id}` con sesion de usuario). Idempotente.

Body:

```json
{
  "tenant_id": "t-demo-1",
  "urgency": "critica",
  "urgency_source": "ia",
  "suggested_note": "Pedir captura del error y revisar el cierre de caja del tenant."
}
```

- `urgency`: `baja|media|alta|critica`. `urgency_source`: `ia` o `prioridad` (si la IA no respondio).
- Debe guardarse en `admin_notes` (o campo propio) **sin cambiar el estado** del ticket ni responder al cliente.
- Validar que `ticket_id` pertenece a `tenant_id`; 404 en caso contrario, sin filtrar existencia de tickets de otros tenants.
- Respuesta 200: `{ "ticket_id": "tk-101", "saved": true }`.

## 2. GET /api/internal/tickets/open?older_than_hours=24

Tickets en estado `abierto` con mas de `older_than_hours` horas desde su creacion. Corre con contexto de superadmin (el superadmin ya ve todos los tickets), solo campos minimos.

Respuesta 200:

```json
{
  "tickets": [
    {
      "ticket_id": "tk-090",
      "tenant_id": "t-demo-1",
      "status": "abierto",
      "urgency": "alta",
      "subject": "Impresora no imprime",
      "age_hours": 30.4
    }
  ]
}
```

- `status`: el flujo solo recuerda `abierto` (los cerrados o en curso no).
- `urgency`: la guardada por `triage` o la prioridad del usuario; `null` si no hay.
- `subject` truncado a 120 caracteres. Sin cuerpo del ticket ni datos de contacto.
- El flujo envia un recordatorio una sola vez por ticket (clave `F03:ticket:<id>:recordatorio-24h`) y solo entre las 8 y las 20 h (Bogota).

## Destinatario

Los avisos van a la plataforma (`tenant_id = plataforma` en I02), canal `default_channel` de `jrpos_config`. Nunca al cliente del ticket.
